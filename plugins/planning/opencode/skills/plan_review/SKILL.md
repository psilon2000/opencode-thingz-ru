# Ревью плана внедрения

Цель: найти дыры в плане до того, как начнётся кодинг.

## Вход

- Если дан путь к файлу — прочитай план.
- Если дан текст — используй его напрямую.

## Что проверять

1) **Постановка задачи**
- Понятна ли цель?
- Есть ли «не-цели» (что сознательно не делаем)?
- Есть ли критерии «готово»?

2) **Подход**
- Соответствует ли подход целям и ограничениям?
- Есть ли проще вариант?
- Есть ли риск «оверинжиниринга»?

3) **Разбиение задач**
- Задачи достаточно мелкие, чтобы делать за 1–3 часа?
- Нет ли «сделать всё» одной строкой?
- Есть ли порядок работ (зависимости)?

4) **Затронутые части системы**
- Перечислены ли ключевые модули/точки интеграции?
- Есть ли миграции/совместимость/обратная совместимость?

5) **Тестирование**
- Явно прописан test plan?
- Есть негативные кейсы и граничные условия?
- Понятно, как проверить в CI?

6) **Риски и откат**
- Есть ли риски и способы их снизить?
- Есть ли план отката (feature flag, rollback, миграции)?

## Формат отчёта

Выводи:

- **Вердикт:** `APPROVE` или `NEEDS_REVISION`
- **Критичные замечания** (если есть) — то, без чего нельзя начинать
- **Серьёзные замечания** — важно поправить, но можно начать с уточнений
- **Мелочи / улучшения**
- **Конкретные правки** (предложи текст/пункты, которые добавить)

Стиль — коротко и по делу.
